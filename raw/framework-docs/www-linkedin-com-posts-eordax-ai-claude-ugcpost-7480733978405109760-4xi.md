 This matches what I keep seeing in production. When an agent misbehaves, the instinct is to add more. More rules, more examples, more edge cases stuffed into the prompt. And it quietly makes things worse.

The newer models flipped that for me. The real unlock has been trusting them to reason and moving the control OUT of the prompt. Fewer instructions inside, stronger tools and verification outside. Shorter prompt, more reliable system.

Cutting 80% of Claude Code's system prompt sounds wild but honestly not surprising anymore. Saving this one.

 the bigger practical gotcha most people miss when switching is the refusal handling. fable can decline something that looks completely benign and it shows up as a normal successful response, not an error, so if your code only checks for failures you'll silently miss those cases. shrinking the prompt is the easy part, rebuilding your error handling around this model's quirks is the part that actually breaks things.
