# Ruben Hassid — Stop Over-Organizing Claude

## Source
- Raw source: `raw/framework-docs/linkedin-com-posts-ruben-hassid-stop-over-organizing-claude-it-slows-you-share-7493980931716939776-k.md`

## TL;DR
The post is a deliberately minimalist counterweight to agent-setup bloat: keep one about-me file and a few usage habits, delete unused prompts/skills/connectors/folders, and avoid dragging stale context into every task; treat it as a low-confidence heuristic, not a universal rule.

## Key Points
- The source argues that over-organizing Claude creates drag: unused prompt libraries, one-off skills, just-in-case connectors, bloated global instructions, nested folders, old chat histories, plugin packs, subscriptions, and partially watched tutorials.
- The proposed keep-list has six items: one about-me `.md` file; goal-oriented prompts instead of step micromanagement; an instruction to ask the user questions first; adversarial self-critique after first draft; fresh chats per task; and delegating hard messy work rather than only trivial jobs.
- Notable claims include: a long chat drags old messages into each reply; micromanaging steps can make the model less useful; self-critique improves first drafts; hard tasks are where AI saves meaningful time.
- Commenters reinforce simplicity and context hygiene: remove anything that has not improved a real workflow in 30 days; models need concise boundaries, clear objectives, and clean context windows more than elaborate prompt libraries.

## Conservative Notes
- Low confidence because the source is anecdotal social content and has no benchmark evidence.
- For Jay, the right application is not deleting durable skills or KB pages wholesale; it is enforcing a usefulness bar: if context does not improve real execution, retire or route it out of always-on context.
