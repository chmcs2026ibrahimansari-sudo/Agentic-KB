# SkillOpt as the Write-Back Mechanism for the Proof-of-Work Loop

## Question

The [[patterns/pattern-agent-proof-of-work-loop|Proof-of-Work Loop]] mandates that agents "convert failures into learning updates before claiming completion" — but the pattern specifies *what* must happen, not *how*. What is the safe write-back mechanism?

## Argument

SkillOpt's validation-gated edit cycle is the missing write-back mechanism that makes the Proof-of-Work Loop's learning-update step operationally concrete. The PoW Loop defines the trigger (a failure receipt) and the audit trail; SkillOpt defines the governed path from failure to skill mutation: rollout → reflect → aggregate → select → update → evaluate, with acceptance gated on held-out validation scoring. Neither is complete without the other.

## Evidence

- [[summaries/microsoft-skillopt]] describes bounded skill edits generated by an optimizer model, accepted only when a held-out validation set shows no regression — a staged alternative to naive live skill rewriting.
- [[patterns/pattern-agent-proof-of-work-loop]] requires failure-to-learning conversion before completion claims but leaves the mechanism unspecified.
- Both pages independently identify the same risk (unchecked self-mutation) and converge on the same mitigation (human-in-the-loop approval for high-impact changes).

Without this pairing, a practitioner implementing the PoW Loop defaults to direct skill rewriting (high blast radius) or skips the learning-update step entirely. With it, the path is: mine failures from the PoW receipt log → generate bounded edits → gate on held-out scoring → stage for human review.

## Counter-arguments & Gaps

- SkillOpt's results are reported on Microsoft's own benchmarks; no independent replication is cited in the KB. The validation-gate benefit may shrink on heterogeneous, low-volume personal skill libraries where held-out sets are tiny.
- The PoW Loop's receipt log may not contain enough signal to drive SkillOpt-style reflection — the loop logs *that* a failure occurred, not necessarily the counterfactual needed to propose an edit.
- `[UNVERIFIED]` The claim that these two mechanisms compose cleanly is inferred from first principles; no source in the KB has actually run them together.

## Conclusion

Adopt SkillOpt's gate as the default write-back protocol wherever the PoW Loop is implemented (Hermes first). Open question: what is the minimum viable held-out set for validating edits to a personal skill library?
